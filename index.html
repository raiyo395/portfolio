Main project · Full-stack · Supabase

Client Portal — one place for freelancers and their clients

Admins set up projects and milestones. Clients log in, see how things are going, approve a milestone or ask for changes, and download their files.

View Live Demo (opens in a new tab) View Source on GitHub (opens in a new tab)

Hit Try as Admin or Try as Client on the login page, no sign-up needed. It runs on its own Supabase project with fake data, and there's a scheduled reset set up so it goes back to normal every night.

Why I built it
Client work gets messy when approvals are scattered across DMs and email. "Did you see my message?" "Which version was that?" I wanted one place where the client can see progress, say yes or ask for changes, and the decision actually gets written down.
What it does
  • Admins create projects and milestones.
  • Clients follow progress and approve a milestone or ask for changes.
  • Every decision is kept in a history, so nothing gets lost.
  • Clients can download the files shared on their project.
How it's built
  • React + TypeScript: the app itself.
  • Tailwind, Vite, React Router: styling, dev setup and routing.
  • Supabase: Auth, Postgres, Storage and Row Level Security.
  • Vitest: tests.
  • Vercel: hosting.
Security
  • Row Level Security is on every table, and a client only sees projects assigned to them.
  • A database trigger only lets a decision go through on a milestone that's actually in review.
  • Users can't change their own role.
  • The file bucket is private, with size and file type limits.
One thing I learned
File storage rules are easier to mess up than I expected. I hit an access-denied bug in the storage policies for client uploads and had to dig for a while to find it. Then on a fresh Supabase project the same policies broke again, because one column is named differently there.
Honest notes
I built this solo. I used AI coding tools, but I read and tested what went in. The demo data is fake and nobody has audited this, so please don't put real client documents in it.

How we'd work together

I try to keep it simple. You know the price and the timeline before I write a line of code.

  1. You tell me what you need

    Send me your idea, your designs or your current code. I'll look it over, work out what's realistic, and tell you the quickest way to get something working. If it's a Web3 thing, I'll also point out two or three things in your flow I'd fix. Free, no strings.

  2. I send a written proposal

    What you get, what it costs, how long it takes. All fixed, all written down before work starts. No hourly billing and no "oh, that's extra" halfway through.

  3. I build it, you test it

    I build in React, TypeScript and Tailwind on serverless hosting. I test on the devices we agreed on, and you get to try a working version before I hand anything over.

I usually reply within 24 hours. I get paid in USDT or USDC. Scope, price and timeline get agreed before work starts.
