Nexus — making Web3 transactions less confusing

A wallet dashboard that shows every step of a transaction, so users don't sit there wondering if it worked or not.

View Live Demo (opens in a new tab) View Source on GitHub (opens in a new tab)

Switch your wallet to Sepolia. No real funds needed.

Why I built it
In Web3 apps, transactions often just... go quiet. A pending transaction looks like the app froze. A rejected signature looks like a bug. Users get confused, open a support ticket, or just leave. I wanted to see if I could fix that with clear UI states.
What it does
  • Shows pending, confirmed, and rejected states clearly so users always know where they stand.
  • Handles declined signatures with a clear message instead of a dead end.
  • Listens for wallet account and network changes so the balance never goes stale.
  • The same pattern works for checkout flows, billing, anything with async actions.
How it's built
  • React + TypeScript: typed UI state so broken states can't render.
  • wagmi: wallet connection, balances, transaction status.
  • viem: the chain client underneath.
  • Tailwind + Vite: fast, responsive UI.
  • Multi-wallet support across different providers.
  • Deployed on Vercel.
One thing I learned
Wallet state can change at any moment — user switches accounts, changes networks, disconnects. Nexus listens for all of that so the UI never shows old data. Sounds simple, but it's easy to get wrong.
Honest notes
I built this solo. I used AI coding tools along the way, but I read and tested everything myself. It's on the Sepolia testnet only — not audited, not built for real money. The allocation table uses sample data.
