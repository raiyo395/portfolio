Main project · Sepolia testnet

Nexus: a wallet dashboard

Nexus connects to a browser wallet, reads the connected wallet's balance from the chain, and shows transaction states such as pending and rejected. It is a portfolio project, built to show how I handle wallet UI.

View live demo (opens in a new tab) View code on GitHub (opens in a new tab)

The demo runs on Sepolia. Switch your wallet to that network and use testnet ETH; no real funds are needed.

The problem
Wallet apps can leave people unsure whether a transaction is waiting, rejected, or done. I built Nexus to make those states clear.
My role
Solo project. I chose the stack, built the interface and the wallet integration, and deployed it on Vercel. I used AI coding tools while building it.
Stack and why
React and TypeScript for typed UI state. wagmi for wallet connection, balances, and transaction status. viem as the underlying client. Tailwind CSS for styling. Vite for the build.
What it does
  • Connects a wallet.
  • Reads the connected wallet's Sepolia ETH balance from the chain.
  • Shows an asset allocation table, using labeled sample data.
  • Tracks transaction state, including pending transactions.
  • Handles rejected signatures.
  • Works with more than one wallet provider.
  • Responsive layout.
A lesson learned
A wallet UI can't assume the wallet's state is current. If the app doesn't listen for account and network changes, it keeps showing the old balance and status after the user switches. Wallet state can change at any moment, so the interface has to follow it.
How I tested
Manual testing on Sepolia with a connected wallet.
Limits
Testnet only, and testnet ETH has no market value. The portfolio table under the balance is sample data and is labeled that way in the app. The project has not been audited and is not built or tested for real funds.

How a project works

Clear scope, clear communication, and a working frontend you can review before handoff.

  1. Free review or project discussion

    Send me your wallet or on-chain flow, website, design, or project idea. For Web3 flows, I point out 2-3 specific things worth improving, free. For anything else, I review the scope and suggest a practical frontend approach.

  2. Fixed-scope quote

    I define the deliverables, price, and timeline before work starts, so the scope is clear from the beginning.

  3. Build and test

    I build in React, TypeScript, and Tailwind, then test the interface across the agreed screen sizes and functionality before handoff.
